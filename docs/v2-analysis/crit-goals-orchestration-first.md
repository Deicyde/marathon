## Goals-Coverage Critique

*(Verified against the repo: the claimed verify-plumbing bug is real — `review.py:326` uses `num`, which only exists inside the genexp at `:281` and does not leak in Python 3, so every successful merge path NameErrors. The design's empirical grounding checks out where I sampled it.)*

### Goal 1 — Claude+Aristotle integration: **A-**
The role table is the cleanest statement of the division of labor anyone has produced for this codebase: Aristotle proves; Claude drafts, steers, reformulates, juries, plans, referees — always as a pure function; Python owns mutation. Escalation step 3 (Claude *changes the task*: restate, split into bridging lemmas) is a genuinely new use of Claude's generality, not just a relabel of `claude_review`. Gaps: (a) the boundary between Aristotle's `ask()` continuation and Claude reformulation is undefined — when do you spend a continuation vs. restate?; (b) Drafter context-bundle construction at 16-chapter scale (what does Claude see, and how is it kept under context limits?) is hand-waved; (c) "manage large pools of agents" is deliberately assigned to deterministic Python, which is defensible but should be acknowledged as a reinterpretation of the goal.

### Goal 2 — minimal human-verified surface: **B**
This is more than "reviews": gate_policy + hard gate + C6 digests is a real mechanism, and "dependency cone of the milestone target + deception tags" is concrete. But it's under-specified at exactly the failure point:
- **Cone size.** The dependency cone of a Stokes-class milestone is plausibly hundreds of declarations. "Only the load-bearing definitions" — load-bearing per *whom*? The pruning from cone to "2 pages" is asserted, never mechanized. This is the entire goal.
- **Digest epistemics.** The digest is generated by Claude — the same actor class that could have misformalized. A scaffolding definition *below* the digest line (wrong measure, degenerate instance) can make every digest statement read correctly while the theorem is vacuous. The design leans wholly on deception tags here, with no calibration plan — note the gate gets calibrated against 42 labeled issues, the digest gets nothing. The digest should at minimum embed `#print axioms` output, instance/typeclass summaries, and the *source-text statements* side-by-side so the human verifies fidelity, not plausibility.
- **Digest rejection path is missing.** Sign → flip all covered statements is specified; reject → ??? (bisect the cone? re-enter the ladder at which granularity?) is not.

### Goal 3 — per-declaration review preserved: **A-**
Strongest goal. One column not two codebases, `/marathon:review` unchanged, real bugs fixed first (week 0), reject-notes bypass preserved, force-push PRs kept as the diff view, mixed mode free. One real hole: semantic rejection cascades. The queue-rebase + auto-fix-task story covers *build* breakage from stacking; it doesn't say what happens to downstream tasks already proven against a now-*semantically*-rejected ancestor.

### Goal 4 — long-timescale referee: **B-**
Not vestigial — fix-tasks with `depends_on` blocking that the Conductor "will not schedule around" is enforcement, and the `coordinateCoframe` example shows they know the failure mode. But it's the thinnest change (Effort: S, "one new output type") against the broadest goal:
- **Large-context is unsolved.** "Whole repo + ledger history" in one pure Claude call has no chunking, persistence, or context-budget story. The goal says *long-timescale, large-context*; the design adds an input and an output type to today's referee and inherits the rest as prose.
- **No prevention, only repair.** The referee acts after sloppy code lands. Nothing routes referee conventions *upstream* into Drafter/Planner prompts (naming schemes, namespace layout, file organization) — which is how you avoid 36 declarations of debt rather than fix-task your way out.
- **No self-accountability loop.** Does the referee re-read its past standing-items against the ledger to confirm fix-tasks actually resolved? Unstated — and that loop is what "fire but change nothing" was about.
- **Reusability/navigability** (cross-chapter dedup, refactoring, module docs) — named in the goal, absent here. "Will not schedule around" also rests on unspecified Conductor priority semantics with 5 tasks mid-flight.

### Goal 5 — seamless UX: **B+**
The hard half is genuinely addressed: the integration branch + bors queue directly answers "branches can't build on each other," and fixing `_maybe_merge_marathon_pr` eliminates manual merges. C2 concurrency kills serialized 66.7h waits; idempotent verdicts kill duplicate-reject noise. Remaining gaps that keep this from "Code Tinder":
- **Card ordering under dependencies.** `depends_on` exists in tasks, but the review session's ordering policy (upstream decls first? cone-aware?) is unspecified — wrong ordering wastes the human's reads.
- **Queue starvation.** A reject costs 20–45 min of Aristotle; nothing speculatively keeps the card stream full, so "read cards, swipe, done" degrades to "swipe three, wait an hour" unless dispatch stays ahead of the reviewer. Needs an explicit prefetch/depth target.
- **Rejection-cascade UX**: what already-open downstream cards/PR diffs look like after a queue rebase is unaddressed.

**Overall:** A serious, well-grounded design — goals 1/3 are nailed, 5 is mostly nailed. The two asserted-not-mechanized spots are exactly the user's crown jewels: digest pruning + digest trustworthiness (g2) and referee context/prevention (g4). Demand a worked example of each (a real digest for an existing chapter; a referee run over Ch.11's actual history) before accepting C6/C7 as designed.
