# Marathon architecture report

Marathon is a Python CLI (`python -m marathon`, entry `marathon/__main__.py:685`) that drives Harmonic's Aristotle prover via the `aristotlelib` 2.x SDK, with Claude (the "Hermes" reviewer role) in the loop as prompt-drafter, live-steerer, rater, and referee. All Aristotle work is async (`asyncio.run` per subcommand); all Claude work is synchronous `claude -p` subprocesses billed to a Max subscription.

## 1. CLI subcommands

- **`skeleton`** (`skeleton.py:699`) — batch-formalizes a textbook. Parses `<folder>/order.txt` (`order.py:25`, header `chapX.tex -> ChapterX` plus indented per-chapter instructions), then for each chapter in order: stages a bundle (chapter `.tex` + `macros.sty` + `marathon.md` + the entire gitignore-filtered `--repo-dir` via `git ls-files`, `skeleton.py:109-161`), fills the static template `prompts/skeleton.md` ("scaffold only, `sorry` every proof"), submits to Aristotle, polls to terminal status, downloads the result tarball, and extracts `<output-base>/<ChapterN>/` into the repo (`_extract_solution`, `skeleton.py:164`). No Claude involved. Strictly sequential; aborts on chapter failure unless `--continue-on-error`. Checkpoints to `<folder>/marathon-state.json`.
- **`refine`** (`refine.py:1080`) — the core loop (§5). Claude reviews → drafts an Aristotle prompt → Marathon submits → extracts in place → optional build/commit/push/rate/PR pipeline → repeat up to `--max-iterations`.
- **`fill` / `fill-file`** (`fill.py`) — thin wrappers that compute a `--focus-directive` ("fill ONLY `X`'s sorry body…", `fill.py:299-327`), force `max_iterations=1`, default-on auto-build/commit/push/rate/PR, and delegate to `refine_command` (`fill.py:202-291`). `fill --issue N` regex-extracts decl names from a GitHub issue's ```lean blocks via `gh issue view` (`fill.py:52-77`).
- **`referee`** (`referee.py:584`) — one-shot Claude agent that rewrites the machine-managed tail (between sentinel comments) of `<repo>/.marathon/referee.md`, scanning repo Lean files, per-chapter workdir artifacts, and git log; optionally auto-commits/pushes. Also triggered inside refine via `--auto-referee-every N` (`refine.py:1350-1390`).
- **`review …`** (`review/cli.py`) — GitHub-sub-issue review workflow: `list/next/show/open/bootstrap-chapter/audit-chapter/verify/reject/refine-status/refine-start/refine-stop/daemon/subissues create|refresh`. Config in `<repo>/.marathon/review/config.toml`. The **daemon** (`review/daemon.py`) is a single-flight loop: while pending rejections exist, shell out `python -m marathon refine … --review-rejection N` one issue at a time (`daemon.py:158-198`), guarded by a PID lockfile `.marathon/review/runner-locks/refine-c<N>.lock`; sleeps in 1s chunks when drained.
- **`formalization init/update/backfill-wall-time`** (`__main__.py:381-472`) — manages a mathlib-initiative v0.2 `formalization.yaml` (auto-fields: sorry counts, models, framework, wall_time; `--check-axioms` batches `#print axioms` through one `lake env lean`). `backfill-wall-time` walks PromptLog project UUIDs and re-fetches authoritative per-task durations from the API (concurrency-limited semaphore, the only place multiple Aristotle API calls run in parallel).

Results land in git via the post-pipeline (§5) — `git add` of the chapter folder + `PromptLog.md` + `formalization.yaml`, commit with Aristotle/Claude co-author trailers (`post_pipeline.py:302-394`), optional push, and `--auto-pr` (dedicated branch `marathon/refine-c<N>[-i<issue>]` reset to `origin/<base>` before the iteration, force-pushed + `gh pr create/edit` after, `post_pipeline.py:497-741`).

## 2. Aristotle invocation

SDK surface (wrapped in `aristotle_runtime.py`): `Project.create_from_directory(prompt, project_dir)` → `project.get_tasks(limit=1)` (`:139-150`); `task.refresh()` polling; `project.ask(prompt)` for continuations and live steering (`:153-169`); `project.get_files(destination)` for the result tar (`:268-274`); `Project.from_id`/`AgentTask.from_id` for reattach (`:172-202`); `task.get_events()` for the event stream (`:280-303`). Status taxonomy at `aristotle_runtime.py:48-97`: retryable = `COMPLETE_WITH_ERRORS|FAILED`; continuable (session preserved, prefer `ask()`) = `COMPLETE_WITH_ERRORS|OUT_OF_BUDGET`; `CANCELED` terminal.

**Polling**: `_poll_task_loop` (`:208-235`) — `await asyncio.wait_for(stop.wait(), timeout=polling_interval)` then `task.refresh()`, default 60s. **Concurrency**: one Aristotle task per process; chapters and iterations are strictly sequential. asyncio exists only so the status poller and the event watcher run concurrently (`run_task_to_completion` gathers both, `:238-262`). Parallelism across chapters means launching multiple OS processes (the README's tmux pattern; the daemon's per-chapter PID locks). Crash recovery: `marathon-state.json`/`marathon-refine-state.json` record `project_id`+`agent_task_id`, and reruns reattach instead of resubmitting (`skeleton.py:616-642`, `refine.py:446-510`).

**Steering**: the `HermesWatcher` (`hermes_watcher.py:213`) polls events every 5s, and on each `EDITING_FILE` event calls Claude with `prompts/hermes_steer.md` (high bar: scope violations, proofs in skeleton mode, referee-forbidden patterns, named API mistakes); a `{"steer":…,"reason":…,"prompt":…,"memory_note":…}` JSON verdict may trigger `project.ask(prompt)` mid-flight (`:329-365`), guarded by a refresh check so it never asks a terminal task. Decisions log to `marathon-steering-log.jsonl`; running notes accumulate in `hermes-memory.md` (tail re-read each call).

## 3. Claude invocation

Always the **Claude Code CLI as a subprocess** (`claude -p --model claude-opus-4-7 --tools "" --output-format text`), never the SDK — `ANTHROPIC_API_KEY` is scrubbed so it uses Max OAuth (`claude_review.py:354-359`). Model env-overridable via `MARATHON_CLAUDE_MODEL` (`claude_review.py:38`). Four Claude roles, four prompts:
- **Reviewer/drafter** (`claude_review.py:114-386`): rubric `prompts/review.md` (proof mode: correctness > cross-chapter dedup > sorry triage > concision > style) or `review_skeleton.md` (`--skeleton`), concatenated with pending-rejections contract, `referee.md`, whole-repo Lean context, `marathon.md`, target folder, refine log, cross-chapter sibling context, rater feedback, continuation/focus-directive sections. Prompt passed via **stdin** to dodge argv `E2BIG` (`:338-346`). Output sent verbatim to Aristotle.
- **Live-steerer**: `hermes_steer.md` (above), prompt via argv (`hermes_watcher.py:445-451`).
- **Rater** (`post_pipeline.py:776-883`): `prompts/rate.md`, 7 scores (quality/math/generality/api/concision/lean4/structural_focus) + notes as JSON, with lenient regex fallback parsing (`:1283-1340`); appends to `marathon-ratings.jsonl`.
- **Referee agent**: `prompts/referee_agent.md` (`referee.py:350-383`).

Plugin slash commands (`/marathon:refine`, `:fill`, `:skeleton`, …) shell out to these CLI verbs.

## 4. State management

Per input folder: `marathon-state.json` (`ChapterState` list — project/task IDs, status string, timestamps, attempts, note; `state.py:10-59`). Per refine workdir: `marathon-refine-state.json` (`RefineState`, `state.py:62-93`), `marathon-refine-log.md` (every drafted prompt), `marathon.md` (Aristotle's design notebook, round-tripped through bundles), `marathon-ratings.jsonl`, `marathon-steering-log.jsonl`, `hermes-memory.md`, `marathon-audit-violations.jsonl`. Per repo: `.marathon/referee.md`, `.marathon/PromptLog.md` (legacy root fallback, `post_pipeline.py:152-172`), `.marathon/wall-time.json` (v2, project-id-keyed — idempotent overwrite per project so parallel branch PRs merge cleanly; the v1 lump-sum counter caused main's wall_time to go *down* on merges, `formalization.py:326-382`), `.marathon/review/{config.toml,runner-locks/}`, plus `formalization.yaml` at root.

JSON state writes are atomic (tmp+`replace`, `state.py:55-59`), but JSONL/PromptLog appends and the wall-time sidecar read-modify-write have **no locking** — concurrent processes can interleave. `RefineState` is a single mutable record reset every iteration (`refine.py:1283-1291`), so only the latest project is reattachable. Known fragility, patched around: `--auto-pr`'s `git checkout -B branch origin/main` wipes the local rejection record, so rejections are prefetched before the branch switch (`refine.py:1195-1210`); dirty `.marathon/` files are auto-committed inline to allow the switch (`post_pipeline.py:533-571`).

## 5. The refine loop end-to-end

Per attempt (`refine.py:862-1056`): (1) gather context — `marathon.md`, refine log, `referee.md` (suppressed under `--review-rejection`), latest rater note, sibling-chapter tails (`:273-358`), pending rejections; (2) **Claude drafts the Aristotle prompt** (`claude_review.review_and_draft_prompt`) — except focused rejections, where the human's reject notes bypass Claude entirely and become the prompt (`:128-165`, rationale at `:949-959`); (3) Marathon appends an output-requirements trailer pinning the output path and `marathon.md` update (`:360-407`); (4) submit fresh (`_submit_fresh_refine`, staging excludes `referee.md`) or continue via `project.ask()`; (5) poll to terminal; (6) on `COMPLETE|COMPLETE_WITH_ERRORS|OUT_OF_BUDGET`, download tar and `_extract_solution`: **wipe-and-replace** the primary chapter folder, **overlay** extra writable paths from review config (cross-chapter refactors, `refine.py:70-125`), wrapper-dir stripping, `marathon.md` back to workdir; (7) only on `COMPLETE` run the post-pipeline: `lake build` (timeout, sorry-noise-stripped log summary, failure non-fatal, `post_pipeline.py:271-299`), wall-time accumulation, `formalization.yaml` refresh, commit/push, verified-decl audit (flags edits to human-verified declarations, soft warning, `:1176-1250`), rater, PR. Failure handling: `COMPLETE_WITH_ERRORS`/`OUT_OF_BUDGET` → continuation via `ask()` with a short surgical prompt (continuation framing in `claude_review.py:265-298`); `FAILED` → fresh submit; retries exhausted → `RETRIES_EXHAUSTED`, loop ends; `CANCELED` ends immediately. There is **no semantic validation beyond `lake build`** — extraction success is "expected folder existed in the tar."

## 6. Pain points

- **Destructive wipe before validation**: `_extract_solution` `rmtree`s the target folder *before* scanning members (`skeleton.py:258-262`); if the tar lacks the expected path (`OUTPUT_FOLDER_MISSING`), the working-tree chapter is already deleted (git-recoverable, but a landmine for uncommitted work).
- **Whole-repo prompts**: the reviewer prompt inlines every Lean file in the repo each iteration (`claude_review.py:70-111`); no caching via CLI (acknowledged trade-off, `claude_review.py:13-19`); escape hatch is the `MARATHON_REVIEW_CONTEXT_PATHS` env var.
- **Inconsistent argv vs stdin**: the reviewer learned the `E2BIG` lesson (stdin), but the rater (`post_pipeline.py:838-845`) and Hermes watcher (`hermes_watcher.py:445-451`) still pass large prompts via `-p argv`.
- **Polling everywhere, no events push**: 60s status poll, 5s event poll, daemon 1s sleep chunks; `_poll_task_loop` swallows `AristotleAPIError` indefinitely with no backoff or failure cap (`aristotle_runtime.py:228-233`).
- **Single-threaded by construction**: one task per process, blocking `subprocess.run` Claude calls (the watcher's `asyncio.to_thread` is the exception, and it's deliberately single-flight, `hermes_watcher.py:20-23`); parallelism = multiple processes sharing one git index (commit step just skips "if the index is busy").
- **Hard-coded paths/hacks**: daemon workdir pinned to `~/Desktop/marathon-runs/review-fixes` ("could be made configurable later," `daemon.py:151-155`); a docstring cites `/tmp/marathon-refine-chapter-scope-bug.md` (`skeleton.py:194`); `--bare` removed because it broke keychain OAuth (`claude_review.py:333-337`); porcelain column-parsing footgun hand-noted (`post_pipeline.py:538-544`).
- **Branch hygiene is patch-on-patch**: plain `--auto-push` pushes whatever branch is checked out (the daemon once committed onto unrelated branches — the documented motivation for `--auto-pr`, `post_pipeline.py:74-83`), and the prefetch/auto-commit workarounds in §4 exist because branch switching and state files fight each other.
- **Partial output limbo**: `COMPLETE_WITH_ERRORS` extractions modify the repo but never run the commit pipeline (`refine.py:783-787`), leaving uncommitted changes that the next iteration's wipe may silently discard.
