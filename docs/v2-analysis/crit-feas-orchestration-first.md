# Feasibility critique: Marathon v2

**Verdict: right diagnosis (coordination layer), but four load-bearing hand-waves.** I verified the cited bugs in code (`review.py:279` iterates dict keys; `num` NameError at the tracker call; `claude_review.py:23` "Claude is never given LaTeX files") — the bug-fix-first migration step is sound. The rest, in descending severity:

**1. C3/C5/C6 quietly demolish the firewall — or the gate can't gate.** The jury's highest-weight rubric is *faithfulness* (w=0.4 in autoform), which requires comparing Lean statements against the book. But the firewall (`claude_review.py:23`, copyright confinement per the geo-local report) forbids Claude from seeing the `.tex` — and C5's "vendored autoform extraction" *is* Claude agents reading the book directly (autoform-relation report: "autoform's agents all read the book"). The design asserts "the firewall survives" without resolving that the extractor breaches it and the faithfulness judge is blind without it. Today the project handles this honestly: informal statements are flagged "⚠️ LLM-rendered from common knowledge; verification pending," and *the human side-by-side check is the faithfulness gate*. Fix: drop faithfulness from the machine gate (keep proof_integrity + axioms + matcher — those need no book), and have digests certify only "deception-free and axiom-clean," not "faithful." Relatedly, **gate calibration on "the 42 verified issues" is a category error**: those are 🟡 *statement* verifications with sorries allowed; nearly all would fail proof_integrity≥3. You don't own the labeled dataset you think you own.

**2. Concurrency is priced in Aristotle-hours but not Claude-calls or shared files.** C2's `asyncio.gather` ignores three things. (a) Harmonic's terms cap concurrent sessions at an *undocumented* limit (aristotle-web report) — N is a number you must discover empirically, with `429`-handling, before sizing anything. (b) Every parallel task implies parallel `claude -p` subprocesses on one Max OAuth session — drafter (whole-repo prompt per iteration, `claude_review.py:70-111`), steerer (per EDITING_FILE), rater, now jury too. Max-plan concurrency limits and the whole-repo-prompt cost multiply by N; the design never mentions it. Fix: a Claude-call semaphore + the already-acknowledged `MARATHON_REVIEW_CONTEXT_PATHS` trimming made default. (c) Worktrees isolate the index, but `formalization.yaml` and PromptLog are committed *every iteration on every branch* (`post_pipeline.py:346, 969`) — N parallel branches all rewriting one YAML file guarantees merge-queue conflicts; this is the wall-time race you just fixed, generalized. Fix: make formalization.yaml a Conductor-side projection regenerated at merge time, never committed by workers.

**3. "Only the Conductor mutates state" contradicts "review verbs work unchanged."** `verify`/`reject` are separate CLI processes; coreviewer/bootstrap agents run `gh issue create` and edit bodies directly (`subissues.py`, `open_session.py`). Routing all GitHub mutations through one process means an RPC/queue surface for the CLI verbs — unscoped, un-estimated. And "labels/comments become a one-way projection" ignores that today's **inbound** verdict channel is the comment thread and body edits (geo-github report: the thread *is* the verdict log). SQLite-WAL gets you 90% honestly: multi-process writes are safe; let CLI verbs write the ledger directly and reserve "Conductor-only" for git/PR/merge operations. Separately, a git-ignored ledger discards the provenance the operator demonstrably wants (PR #74 exists *to track a verify in git*) — add a tracked append-only verdict-export JSONL.

**4. The merge queue meets 20–45-minute stale bundles, and stacking meets human rejects.** A task submitted from integration-head@T lands after the head moved; Aristotle can't rebase its own output, so cross-file signature changes (#50→Ch.12) still conflict — the queue converts four-day red-main into frequent rebase-conflict fix-tasks, i.e., more Aristotle spend, not less. Worse: "reviews can finally stack" + "human verify is the only path to main" are in tension — a reject of a mid-stack item has no rollback story. Fix: stack only `gate_policy=auto` work; keep human-gated tasks based on `origin/main` (today's deliberate choice). 80% of the win is just the auto-spawned fix-task on post-merge build breakage.

**5. Reformulation (ladder step 3) re-opens the wound the Claude-bypass cauterized.** Claude was removed from rejection prompts because it substituted its own agenda (`refine.py:949-965`); now gate failures feed a Claude *empowered to restate lemmas* — including 🟡 statements a human verified against Lee at a pinned SHA, with only a regex-grade audit (`verified_decls.py`) watching. Fix: reformulation forbidden on human-verified targets; any signature change auto-demotes 🟡→🟠 and re-queues review.

**Smaller:** a blocking gate would have held PR #99 hostage (its `[build:FAIL]` deletion was the thing the human wanted) — ship a `--gate-override`; the operator's red-main tolerance is a workflow, not an accident. C6's deception-tag metaprogram is Lean-toolchain-pinned (`Mathlib_4_30` backports in-repo) — porting it is unbudgeted. C1 "Effort M" is optimistic: it rewrites the most fragile 2k lines on a live project whose last harness patch generated 11 re-queue comments on one issue (#49); run shim and legacy state dual-written for a full chapter before cutover, not "imported once."

**Keep:** week-0 bug fixes, gate-as-advisor-first, Conductor-dispatches-existing-subprocesses (step 4), and everything in "NOT building" — that section is the design's most credible part.
